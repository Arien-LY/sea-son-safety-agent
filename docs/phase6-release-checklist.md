# Phase 6 发布验收表

本表用于比赛演示版本，不等同于生产上线审批。每位执行人必须从仓库重新克隆，不复制既有`.venv`、
`node_modules`、`.env`、`data/*.json`或`uploads/`。真实密钥不属于安装验证。

## 自动化入口

在仓库外的 PowerShell 执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify-clean-clone.ps1 `
  -Repository <私有仓库URL或本地仓库路径> -Branch main
```

脚本只在系统临时目录创建`sea-son-clean-clone-<GUID>`，校验目标路径后才在成功时清理；失败时保留
目录供排查。它拒绝克隆中出现`.env`、`uploads/`或`data/*.json`，随后执行`setup.ps1`与
`verify.ps1`。执行人仍须记录操作系统、Python、Node和Git版本。

## 浏览器完整流程

使用 Mock/Fake 验收时须持续显示“未执行真实模型”；不得把预设分类、图片观察或延迟当作真实能力。

1. 新建聊天发送“你好”，确认用户消息立即靠右、输入框清空、Fake回复靠左、用时可展开。
2. 新建咨询先发“配电箱怎么了”，确认只追问、不出现工单；再发“三层配电箱冒火花且有人在附近”，
   确认高风险、立即避险、人工复核和待确认提案入口。
3. 生成提案、核对锁定风险字段、人工确认并显式保存草稿。
4. 人工执行提交、派工、开始整改、提交整改、专业复查关闭；确认revision递增且事件只追加。
5. 刷新详情并从历史工单重新打开；检索“临边”或“消防通道”，确认来源、适用范围和人工结论分区。
6. 上传合成/已打码图片，确认授权、脱敏预览、Mock不声称识别；图片失败不妨碍文字工作流。
7. 在390×844检查侧栏抽屉、消息滚动、工单表单、代码块和底部输入，无整页横向溢出。
8. 控制台不得出现未解释的error/warning；Network不得访问模型供应商或远程图片像素。
