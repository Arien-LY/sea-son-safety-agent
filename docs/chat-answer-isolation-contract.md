# 聊天正文与工单分析失败隔离

目标：辅助工单分析无效时，不丢弃完整可用的聊天正文；保留快速/深度选择与真实流式输出。
教程依据：Hello-Agents V1.0.3 第7章结构化边界、第9章会话、第12章回归、Extra09错误可观测性。
当前行为：同一个JSON中任意分析字段不合法，会整体拒绝回答、清空临时正文。
允许修改：文字适配、响应v4、会话/展示、测试、客户打包及验证记录。
禁止修改：冻结旧版契约、工单权限与状态机、真实密钥/用户数据、付费自动重试。
测试命令：专项pytest、前端行为测试、scripts/verify.ps1、Windows包验证。
人工确认点：降级回答不是风险结论；工单仍须有效分析与人工确认。

## 验收

- I01：auto返回合法且无重复键的完整JSON，answer通过独立Pydantic字符串校验时，
  analysis缺失、类型/枚举/必填字段错误或追问格式错误，只令分析不可用，不丢正文。
- I02：服务端响应analysis_status=unavailable；分析替换为程序构造的unknown/undetermined、
  需人工核验占位，不接受模型伪造的状态。不能由此跳转或创建工单。
- I03：降级正文进入已成功对话，重放不重复调用，后续历史问答配对；不沿用上轮工单资格。
  既有high/emergency避险提示仍保留，不能解释成风险解除。
- I04：空/非字符串/超长正文、JSON截断/重复键、连接中断仍拒绝，恢复输入，不写入历史。
  不用正则抢救损坏JSON，不读取隐藏思维链，不额外调用模型。
- I05：旧consult严格校验不变；正常有效分析的自动工单引导不变。
- I06：客户根目录仅海之子.exe、使用说明.txt、_internal；声明与完整许可收纳到
  _internal/licenses，不能遗漏分发组件要求随附的文本。

本契约取代chat-regression-contract R04中“分析字段错误也丢正文”的行为。
仍使用单次结构化生成；独立的是校验/失败处理，不宣称取消所有约束或验证真实模型质量。
