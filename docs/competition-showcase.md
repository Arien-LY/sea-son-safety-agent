# 比赛展示材料提纲

## 一句话定位

海之子把施工现场的一句自然语言或一张图片，转成“可追问、可核对、可人工确认、可追踪整改”的受控
闭环；AI负责建议，确定性代码和专业人员拥有业务状态。

## 建议 8 页展示结构

1. **痛点**：描述模糊、风险易漏、依据难追溯、聊天结论无法形成整改闭环。
2. **产品入口**：普通聊天 / 专业咨询 / 直接提交三条路径；只有满足条件才出现工单步骤。
3. **系统边界**：单Agent结构化分析 → 待确认提案 → HMAC确认 → 六状态确定性工作流。
4. **安全设计**：高风险立即避险与人工复核；AI不能派工/归责/关单；失败关闭和脱敏审计。
5. **依据与图片**：可追溯小知识库；单图只作初步证据，观察/不确定/未观察到分开。
6. **产品体验**：Codex式简洁对话、用户消息靠右、等待秒数、服务端步骤、响应式历史工单。
7. **评估证据**：20案例与70个要点；成功和故障Trace；Fake、真实模型、人工裁决严格分层。
8. **现状与路线**：本机演示已完成；真实准确率、生产身份/数据库、双机签字是明确发布门禁。

## 可安全使用的数字

- 20条冻结文字案例：咨询、安全、质量、管理、后勤各4条；70个必须提取/追问要点。
- 结构化合成协议回放：分类20/20、高风险7/7、路由20/20、工具行为20/20；这是协议测试。
- 失败回放：1次高风险超时使召回降为6/7且总报告失败。
- 工作流6个主状态；知识目录2份公开法规、8条释义；图片最多5个候选。
- 当前自动验证结果以`docs/verification.md`最新记录为准，演示前不得口头扩大范围。

## 禁止使用的宣传语

- “真实工地识别准确率100%”“AI自动判定事故责任”“自动派工并关单”。
- “已经生产上线”“具备企业级登录权限”“支持多机并发数据库”。
- “引用即代表合规结论”“EXIF清理后图片没有隐私”“停止按钮保证不会计费”。
- 把Fake/Mock、合成图或协议Trace描述成真实模型/真实现场测试。

## 答辩常见问题

**为什么不用多智能体？** 当前闭环只需一个分析边界；增加Agent会扩大状态、成本和追踪难度。业务状态
由代码推进比让多个模型互相决定更可审计。

**模型判断错了怎么办？** 信息不足会追问，高风险必须人工复核；结构化输出不合格就失败关闭。图片候选
可逐项纠正/驳回，正式工单仍需人工确认，状态变化保留事件轨迹。

**如何证明不是演示拼接？** 提供冻结Schema、20案例、成功/失败Trace、全新克隆脚本、完整pytest、
前端行为测试和生产构建；失败案例会进入分母并使门禁失败。

**能否直接上线？** 不能。当前是单机受控演示，生产身份、数据库、隐私治理、真实数据专业评估和双机
复现仍是明确门禁，详见`docs/known-limitations.md`。
