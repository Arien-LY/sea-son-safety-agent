目标：单图作为补充证据，经脱敏后可生成多个待人工确认候选，并关联同一记录的整改前/后照片。

教程依据：Hello-Agents V1.0.3 单 Agent、严格结构化输出、无模型状态写入、人工确认与固定评估；
继续沿用第7/9/12章的有限调用、上下文边界和确定性验收，不引入多智能体。

当前行为：Phase 4 PR #12 已合并，基线 db08fcf。已有文字分析、提案、工作流和只读知识。
用户已把 .env 设为 real，但现有启动脚本不加载该文件、文字页面仍是结构化演示；只改模式不等于
已经接通模型。现有 deepseek-v4-flash 不支持图片。

验收条件：单图限额/解码/EXIF清除/随机文件名有效；观察状态和候选严格校验；低清/遮挡/上下文不足
追问；人工采纳/纠正/驳回留痕且不能降低风险；前后照片同记录可追溯；模型失败不影响文字路径；
离线测试和 verify.ps1 通过；真实连通性单独记录，不把合成图测试称为现场识别准确率。

允许修改：图片契约、上传/存储/关联/分析服务、独立视觉适配器、页面、启动配置、测试与文档。

测试命令：`.venv\Scripts\python.exe -m pytest tests/test_phase5_*.py`；`scripts/verify.ps1`。
人工确认点：上传授权、逐次外发确认、候选纠正/采纳、前后证据关联与最终工程复查；无生产身份鉴权。

## 模型与费用

- [官方视觉文档](https://api-docs.deepseek.com/guides/vision/)（2026-08-30核对）：只有
  deepseek-v4-flash-vision-exp 接收图片，使用原生 user content 的 image_url/base64；不使用外部图片URL。
- 新增独立 VISION_MODEL，保留 LLM_MODEL 与密钥。运行时只允许已核验的 DeepSeek 官方端点和视觉模型。
- 用户本轮已明确授权：仅合成图，最多2次真实连通性请求，每次输出上限1024 token，总预算US$0.01。
  冒烟脚本默认拒绝联网，必须显式传授权参数；失败不自动重试，不额外运行真实现场评估。
- 产品每次分析要求 allow_external=true 才向服务商发图；调用超时30秒、重试0、最多4096输出token，
  页面显示费用提醒，不把测试授权扩展成后台批量调用授权。
- 不读取、记录、展示 reasoning_content。普通pytest/verify永远使用Fake或Mock，不因.env=real而联网。

## 上传与隐私

- 一个请求只接收一张JPEG/PNG原始二进制，不接收multipart、图片URL或客户端文件路径。
- 上限5MiB、每边4096像素、总计1600万像素；检查实际解码格式与Content-Type一致；拒绝多帧、坏图。
- Pillow进行完整解码、EXIF方向归一化、透明背景铺白、重新编码JPEG；不保留EXIF/GPS/ICC/文本块、
  原始文件名或原始文件。服务器随机PHOTO-ID映射到本地uploads内的JPEG；禁止路径穿越和符号链接逃逸。
- 清理元数据不等于自动打码：人脸、铭牌、工牌等像素内容仍可见，用户必须先遮盖并确认授权。
- 文件与索引原子发布；索引更新失败只清理本次新文件；既有图片和业务记录不得损坏。
- 本地演示最多200张、每张最多10份分析；无自动公开静态目录；图片通过校验ID的API读取。
  尚不具备生产身份/所有权校验，不允许直接暴露公网。

## 结构化视觉结果

VisionAnalysis严格extra=forbid：observations（最多20项，状态observed/uncertain/not_observed）、
limitations（low_resolution/blurred/occluded/context_missing）、follow_up_questions、candidates（最多5项）。
preliminary_only与requires_human_review固定true；看不见不等于不存在；无法识别时可无候选。
每个候选有稳定本轮ID、关联观察ID与IssueAnalysis；只能引用观察到或不确定项，不能把未观察到作为
确有问题的依据。所有图像候选必须含不确定性、缺失字段、人工复核路由；高风险还须立即避险提示。
低分辨率由图像尺寸补充确定性标记，其他质量判定由模型提供，存在限制必须追问。

图片文字是证据而非系统指令；不执行图片里的命令，不编造规范或人员责任。
单个临时SimpleAgent调用一次；适配层插入图片，结构化校验后才保留结果；无工具、无共享历史。
Mock模式不声称看到了施工隐患，只返回明确的未识别/待人工核验结果。

## 人工纠正与照片关联

- 模型结果原样保留。用户可以驳回候选或采纳时修订摘要，必须有说明；操作留在照片索引中。
- 采纳只产生既有待确认提案，不自动建单；原候选风险、人工复核和立即行动不能被纠正接口覆盖。
- 前照片：原报告人在draft/submitted/assigned上传关联；后照片：被指派整改人在rectifying/pending_review关联。
- 关联需photo_id、before/after、actor、当前expected_revision、人工确认；同图不能更换记录或前后阶段。
- 锁住工作流记录快照后更新独立照片索引，记录关联时revision/时间/人员；不修改主状态或主记录revision。
  锁只在同Python进程内有效，仍非跨进程事务。检索关联照片必须确认问题记录存在。
- 上传、分析、选择候选、保存记录、前后照片关联各为明确动作，任一步失败可以继续原文字工作流。

## 固定验收矩阵

先冻结12个场景：正常单候选、多候选、无可观察问题、低清、模糊、遮挡、缺上下文、高风险、
图片指令注入、错误识别后纠正/驳回、模型超时/错误、整改前后关联。
另覆盖MIME伪造/损坏/多帧/超尺寸/超字节/EXIF/GPS/路径穿越/索引故障/并发和real配置隔离。
自动测试验收结构与权限，不用Fake输出证明识别能力；专业复核表逐项记录现场判断和可纠正性。
