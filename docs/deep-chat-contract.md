# 普通聊天深度思考与容量升级（2026-08-31）

目标：普通聊天从演示级快捷短答调整为有深度思考、充足回答预算和多轮上下文的日常聊天。
教程依据：Hello-Agents V1.0.3第7章基础对话、第9章上下文预算、第12章协议与效果分离评估、Extra09可观测性。
当前行为：thinking disabled、256输出token、10秒模型/35秒页面等待、1000字输入与回答、6轮即停。
验收条件：D01–D07；按用户新要求替代旧普通聊天容量约束，专业咨询和Phase1/3冻结契约不变。
允许修改：普通聊天预算配置、产品层输入/响应v2契约、上下文选择、会话容量、前端输入/等待提示和测试文档。
禁止修改：.env/密钥、专业咨询模型与风险规则、业务状态权限、自动工单、多智能体、图片/RAG、隐藏推理展示。
测试命令：相关pytest、前端行为测试、scripts/verify.ps1、隔离Fake浏览器验证。
人工确认点：真实调用由用户主动发送并承担费用；没有真实效果/速度保证，不自动合并PR。

## 配置与兼容性

| 普通聊天项 | 旧值 | 新值 |
|---|---|---|
| 深度思考 | 关闭 | enabled / reasoning_effort=high |
| 输出token预算 | 256 | 32768（预算上限，不要求写满） |
| 模型等待 / 浏览器截止 | 10 / 35秒 | 180 / 190秒 |
| 单条用户输入 | 1000字 | 16000字 |
| 最终回答 | 1000字 | 64000字 |
| 会话轮数 | 6 | 50 |
| 模型历史 | 所有最多5对 | 最近最多12对且user/assistant正文合计≤120000字 |
| 单会话累计内容 | 按旧轮数自然限制 | 新请求前已有输入/答案加当前输入≤400000字 |

- 预算集中在agents/chat_settings.py；输入和输出仍经过Pydantic。普通聊天不强制短答或固定格式，按问题
  复杂度提供必要的依据、解释、例子和可检验步骤，不输出隐藏思维链。
- 当前输入始终完整保留；只从最旧的完整历史对开始省略，不拆开问答。响应context_trimmed显式告知前端。
- 所有成功响应仍用于幂等；容量上限不是删除历史。一次输出可能使总内容超过400000字，回答照常返回，
  下一轮明确要求新开聊天；最多额外64000字，避免付费后因容量阈值丢弃答案。
- 产品请求/响应新增v2快照，保留v1文件；原HTTP路径、字段和旧短输入兼容。新增context_trimmed默认false。
  Phase1 TextConsultationInput、TextReply专业咨询限制与专业咨询6轮/1000字输入/30秒/4096token不变。
- 普通聊天超时变长时页面可取消等待/切换导航，取消不保证供应商停止计费；零自动重试保持不变。
- 非空截断回答保留并明确附加“达到本次输出预算”提示，而不是丢弃整段；只有思考而无最终content仍明确失败。
- 只读最终content，不读取/保存/回传reasoning_content；深度思考配置不等于可获知模型内部当前步骤。

## 固定验收

- D01 Fake SDK核对enabled/high/32768/180、长回答通过产品API；consult仍disabled/4096/30。
- D02 超1000字普通聊天输入可用，consult拒绝；空/超16000/伪造字段/权限仍拒绝；v1快照不改。
- D03 7轮聊天成功、50轮上限、内容容量门禁；失败/重放/新会话隔离与原逐轮回归不回退。
- D04 按轮数和总字数完整裁剪旧问答，最新输入保留；context_trimmed准确；consult不裁剪现场事实。
- D05 有最终content的截断明确展示预算提示，空/超长/工具/超时失败；不读取隐藏推理。
- D06 前端chat190秒/consult35秒截止覆盖正文，长输入、停止等待、恢复输入与取消晚到回调正确。
- D07 等待/完成/手机布局、长回复和上下文提示用隔离Fake验证；不把Fake内容当作真实模型质量验收。
