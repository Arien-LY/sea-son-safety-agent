# 比赛演示脚本（约 8 分钟）

## 演示前准备

- 使用单独的 Mock/Fake 演示目录，不加载真实`.env`，清空临时记录。
- 打开首页、历史工单页和`docs/phase6-protocol-report.v1.json`。
- 准备一张不含真人/工牌/手机号的合成PNG。确认右上角显示Mock或模型配置状态。
- 不在投屏中展示API密钥、本机用户名、真实项目名称、真实人员信息或浏览器开发者令牌。

## 0:00–0:45：一句话问题与价值

讲解：施工现场问题常从一句模糊描述开始，真正难点不是“让AI多说”，而是把信息不足、高风险、
引用依据和整改状态放进可审计边界。海之子是单Agent入口加确定性业务工作流，AI不能自行派工或关单。

## 0:45–1:30：普通聊天

进入“新建聊天”，发送“安全帽下颏带怎么检查？”说明用户消息立即靠右、回答为安全Markdown、
执行区只显示服务端阶段和用时，不展示或伪造思维链。普通聊天不会产生工单按钮。

## 1:30–3:15：专业咨询与高风险保留

进入“新建咨询”，先发送“配电箱怎么了”，展示缺失字段和追问；再发送“三层配电箱冒火花且有人
在附近”。展示高风险、立即远离、人工复核和生成提案入口。强调模型输出先过严格JSON校验，信息不足
不猜地点、责任或现场状态。

点击“生成待确认提案”。修改一个允许编辑的展示字段，展示确认前后差异；指出风险、路由和人工复核
字段被锁定。点击人工确认，再显式“保存为正式草稿”。确认前没有正式记录，确认也不等于自动落库。

## 3:15–5:15：六状态整改闭环

依次演示：报告人提交 → 协调员人工派工 → 整改人开始整改 → 提交整改说明 → 专业复查人关闭。
指出每一步都有角色、revision、时间与说明；高风险报告人不能自关，模型也没有状态写权限。

刷新页面并从“历史工单”重新打开，证明正式记录由服务端本地Store恢复，不依赖聊天界面内存。

## 5:15–6:15：依据与图片证据

检索“临边”，展示模型建议、带来源/版本/适用范围的检索依据和人工结论三分区；无匹配时明确无依据，
不会生成条款号。上传合成PNG并确认本地授权；Mock只返回“未执行识别”，不伪造看见隐患。说明EXIF
清理不等于像素打码，真实图片必须先人工打码和授权。

## 6:15–7:15：评估证据

打开Phase 6成功报告：20案例分类20/20、必需要点70/70、高风险7/7、安全计数0。立即补充：这是
`synthetic_protocol`，只证明协议与评分器。再打开失败报告，展示一次高风险超时使召回变为6/7且
总门禁失败，证明失败不会从分母消失。Token、费用和真实闭环缺数据时显示`not_measured`。

## 7:15–8:00：边界与结束语

明确尚未完成：生产登录/项目隔离、跨进程数据库、真实现场准确率、真实文字20案例与第二台物理电脑
签字。结束语：本项目的创新不是让模型越权，而是让“建议—证据—人工决定—状态变化”可以被验证、
复现和追责。

## 演示故障降级

- 模型不可用：切换到Mock并明确说明，只演示协议、人工门禁和工作流，不伪装真实回答。
- 图片失败：继续文字咨询和结构化提交，展示图片失败不会阻断主流程。
- 浏览器刷新：从历史工单恢复已保存记录；未保存聊天丢失属于当前已知限制。
- 端口占用：使用隔离的8018/5178端口，不停止或覆盖队员正在运行的服务。
