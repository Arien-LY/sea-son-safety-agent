# 普通聊天逐轮上下文修复

目标：修复“身份 → 日期 → 现场问题”连续聊天中旧问题被再次回答的上下文结构诱因。
教程依据：Hello-Agents V1.0.3 第7章基础对话、第9章有限可信上下文、第12章回归与Extra09失败留痕。
当前行为：Chrome DevTools原始第三轮响应已含身份和日期；每轮只有一次发送。当前适配器将所有提问
与上一轮完整回答放在一条user消息中，没有独立当前问题，也没有assistant历史角色。
验收条件：见H01–H06。自动验收只证明输入角色/顺序和程序行为正确，不冒充真实模型生成效果验证。
允许修改：普通聊天模型请求构造、服务端已成功会话历史读取、对应Fake测试和文档。
禁止修改：前端视觉/回复删词、专业咨询累计分析、公共请求响应Schema、业务权限/人工确认、依赖和.env。
测试命令：`pytest tests/test_chat_turn_history.py tests/test_product_text.py tests/test_chat_progress.py`；
`powershell -ExecutionPolicy Bypass -File .\scripts\verify.ps1`。
人工确认点：不调用付费模型、不自动合并；真实聊天重复率需操作者另行主动抽样。

## 上下文与所有权

- 仅chat使用 `system → user₁ → assistant₁ → … → user当前`；最后一条user只含当前输入及其背景标签。
- user正文继续JSON编码一个TextConsultationInput（message/project/area/requester_role），不混入历史问题
  或回答；assistant正文只取服务端已校验成功响应中的answer，不包含analysis、追问结构或隐藏推理。
- 历史答案从已有会话responses按turn读取，不新增独立历史存储；输入仍由已有inputs提供。
- system保留日期、真实配置模型标识、安全边界，明确只回答最后一条user消息。历史角色不授予业务权限。
- 最多6轮，即1条system、最多5对历史消息和1条当前user；历史答案须与历史输入一一对应。
  数量不匹配、空答案、非字符串或超长答案在打开模型客户端前失败，不静默截断/错配。
- 成功响应才进入历史；失败不推进，幂等重放不追加历史，不重调模型；不同会话/intent不串线。
- 10秒超时、0重试、256输出token、无工具及chat禁止提案保持不变。已有会话刷新/重启规则保持不变。
- consult仍累计用户陈述并带上轮追问，保留高风险跨轮边界；不为避免重复而丢弃现场安全上下文。

## 固定回归

- H01 单轮/三轮完整HTTP→服务→SDK：身份、日期、围栏问题分别构成当前user；第三轮严格6条消息。
- H02 追问“把它改短”、标签和伪system字符串：历史完整配对、角色来自程序、系统消息不含用户伪指令。
- H03 SDK失败后同请求重试、成功幂等重放：无重复历史；新会话只含自己的当前输入。
- H04 第6轮最多12条消息；第7轮/客户端伪造历史被拒绝且不调用SDK。
- H05 非法历史长度/内容在外发前失败；SDK超时、截断、空/过长回答、工具返回仍明确失败。
- H06 专业咨询、保留高风险、服务端事件、前端等待/消息/取消等既有回归全部通过。
