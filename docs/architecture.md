# V0 架构

```text
Vue 3 SPA
  └─ HTTP API
       └─ FastAPI
            ├─ API/数据校验
            ├─ 确定性问题工作流
            ├─ 原子本地 JSON Store
            └─ Agent boundary
                 ├─ Hello-Agents 单 Agent
                 ├─ Pydantic/JSON Schema 结构化输出
                 └─ 最小受控 ToolRegistry
```

## 当前已经实现

- 前端起始页和运行状态检查。
- 后端 `/health`、`/api/runtime`。
- Agent 配置、问题分析 Schema、工具统一返回协议。
- 严格文字输入契约，以及无工具、无共享历史的单 Agent 基础对话边界。
- 冻结的 `IssueAnalysis` JSON Schema 与严格结构化输出解析边界。
- 无工具、无共享历史的 `IssueAnalyzer`，结构化分析协议支持六个主类别和五级风险。
- 信息不足和高风险的确定性跨字段门禁：缺失信息必须显式列出并说明不确定性；高风险和紧急风险
  必须给出避险提示、标记人工复核并路由人工复核。
- 覆盖 20 条固定案例及正常、空输入、非法 JSON、超时、模型错误的离线 Fake LLM 协议测试。
- 独立的 `propose_issue_record` 工具契约与最小注册表；当前只生成明确未保存、未派单的待确认提案，
  已通过单工具 FunctionCallAgent 接收严格校验且不可由模型改写的 `IssueAnalysis`。
- FastAPI 提案预览与确认边界，以及 Vue“建议创建记录”页面；用户只能编辑记录展示字段，页面和
  服务端均展示确认前后差异，确认结果仍不持久化、不派单。
- 容量受限的进程内工具审计缓冲区，只记录工具名、参数键名和摘要哈希、结果、时间与错误码。
- 经 HMAC 完整性校验的确认提案可以显式保存为正式草稿；创建使用持久化幂等键。
- 六状态确定性工作流、独立取消处置、revision 乐观并发和完整业务事件轨迹。
- 责任角色只按类别提供建议；协调员人工选择责任人和角色后才进入派工状态。
- 安全、质量、管理和后勤复用同一生命周期；高风险关闭要求独立专业复查人。
- 本地 JSON Store 使用同路径进程锁、临时文件、`fsync` 和原子替换，解析失败时拒绝覆盖。
- 本地只读 `search_knowledge`：8 条有来源的短释义，地区/类别/复核期限过滤、关键词排序和最多3条引用。
- 引用元数据与正文由目录确定性组装，带 SHA-256；不接受模型自由生成的来源或人工结论。
- `KnowledgeAssistedAnalyzer` 在已有一次分析后检索，故障保留原分析；普通咨询和问题工作流均不依赖知识库。
- API/页面区分未核验建议、候选检索依据和持久化工作流中的人工复查结论。
- 单图二进制上传边界、Pillow完整解码和无元数据JPEG重编码，独立本地PhotoStore与内容完整性校验。
- 临时无工具SimpleAgent进行一次视觉分析，严格VisionAnalysis输出，最多5个候选，全部要求人工复核。
- 独立VISION_MODEL，real逐次外发确认、30秒超时、0重试；Mock不声称执行图像识别。
- 人工候选纠正/驳回留痕及既有待确认提案桥接；纠正不覆盖原风险、路由或人工标记。
- 前后照片关联索引记录同一record_id与关联时revision；工作流锁定快照，图片不更改主记录状态。
- 独立TextAssistant每轮一次结构化调用，同时返回回答、追问及原IssueAnalysis；无工具或业务权限。
- 文字API服务端维护有界临时会话及幂等请求，高风险跨轮保留；提案只使用最新服务端分析，成功后冻结会话。
- 文字real外发逐次确认，复用LLM_MODEL；Mock明确不执行文字理解。真实适配器本轮仅用Fake SDK验收。
- `/records`查询本地记录摘要，`/records/:recordId`详情从后端恢复，继续原工作流并展示照片和依据。
- Vue 会话工作台用独立 `/chat`、`/consult`、`/submit` 入口表达三种用户意图；左侧只恢复正式工单，
  未保存会话不伪装为持久历史。普通聊天开启深度思考high，使用180秒/32768-token预算且不暴露提案动作；专业咨询
  使用30秒/4096-token严格结构化分析，只依据服务端 `can_propose` 进入提案链。两种意图不能共用会话。
- 自动测试和前端生产构建。
- 普通聊天上下文按user/assistant逐轮配对，当前输入单独作为最后一条user；答案从会话现有成功responses
  按turn读取，不新增第二份历史存储。chat最多50轮，每次只发最近最多12对且正文≤120000字；裁剪显式提示。
  会话累计输入/答案400000字门禁，单条16000字/答案64000字；产品v2 Schema，Phase1/3及v1快照保留。
  失败和幂等重放不追加；专业咨询累计分析不变。预算集中在agents/chat_settings.py。
- 文字及文字提案新增NDJSON执行事件：排队、准备、模型调用、结果校验、真实工具调用及完成；
  进度内容不含模型思维链。前端仅计量经过时间；正式回复仍在校验后一次显示，不逐token输出；
  chat非空预算截断回答保留并附未完成提示，consult仍拒绝截断JSON。
- 局域网HTTP使用getRandomValues兼容请求ID；发送准备错误可恢复，chat等待190秒、consult35秒，
  停止等待保留原请求ID以便幂等重试，不保证远端停算/停费；聊天取消与业务表单禁用范围分离。
  服务端文字操作锁最多排队1秒，繁忙时返回可手动重试的text_busy。
- 聊天 composer 单张图片附件：原生选择器与窗口/输入框拖放共用同一校验路径，仅 JPEG/PNG、≤5MiB，
  输入框内显示可移除缩略图。发送时先走原有 `/api/photos` 上传取得 `photo_id`，再与文字合并成同一次
  文字请求；图片路由与聊天服务共享同一 PhotoStore，没有第二套上传接口。
- 产品文字请求 v6 增加可选 `photo_id` 与 `allow_image_external`，响应回带 `photo_id`；v1–v5 冻结快照不变。
  `intent=consult` 不接受图片；只发图片时由服务端补默认描述；会话持久化只保存图片 ID，不保存 base64。
- 真实图片轮次仍复用原有单 Agent 与工具循环：DeepSeek Chat Completions 最后一条 user 内容为
  `[{"type":"text",…},{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,…","detail":"original"}}]`，
  模型标识 `deepseek-flash`；不传公网图片 URL，不新增工具架构。
- 图片外发门禁在服务端：real 模式必须本次 `allow_image_external=true` 且 `VISION_MODEL` 已配置，
  否则拒绝；Mock 模式不调用图片模型，界面也不声称本轮使用视觉模型。
- 含图片的工程类分析强制 `requires_human_review=true`、`recommended_route=human_review` 并补充不确定性说明；
  工单状态机与确认权限未改。

## 当前明确未实现

- 真实文字接口独立冒烟、文字/图像现场准确率与专业验收（视觉仅完成过合成图连通性验证）。
- 跨刷新或跨重启的持久聊天历史、逐token流式回答、并行多会话高吞吐；当前会话使用单进程锁且有容量/时效上限。
- 真实登录身份、项目权限、跨进程/跨主机锁、生产数据库、外部派单和通知。
- 历史轮次的图片不重新外发（只保留文字说明）；多图联合分析、自动人脸/工牌像素打码、真实图片识别指标验收。
- 向量库、嵌入模型、重排序模型、自由生成的法规回答、OCR、通知和外部企业系统。

## 目标调用链

```text
用户文字/照片
  → 输入边界校验（图片先经 `/api/photos` 解码、清元数据、重编码，请求只携带 photo_id）
  → 单 Agent 生成 IssueAnalysis（含图片时同一工具循环传 image_url 数据 URL）
  → 普通咨询：直接回答
  → 需跟进：生成问题记录提案
  → 用户确认
  → 完整性校验并保存正式草稿
  → 确定性工作流落库与 revision 并发控制
  → 人工整改与复查
```

## 状态所有权

- 浏览器只展示服务端状态。
- FastAPI 工作流服务是问题记录状态的唯一事实来源。
- Agent 只能返回分析和动作提案，不能直接写数据库。
- 知识材料是依据来源，不能替代专业人员结论。

## 安全设计

- 高风险判断始终要求人工复核。
- 信息不足时显式返回缺失字段和不确定性，禁止猜测地点、人员、现场状态或责任。
- 立即行动只用于降低暴露和阻止危险扩大，不构成最终工程方案或无资质操作授权。
- 图片识别结果区分事实观察和推测。
- 不将隐藏思维链写入日志，只记录动作理由摘要和工具结果。
- 所有会产生副作用的动作由代码判断权限和确认状态。
- 用户只能编辑提案的展示字段，不能通过确认接口降低风险、改写路由或取消人工复核。
- 确认结果固定 `persisted=false/dispatched=false`，Phase 2 没有数据库或派单器依赖。
- 工具审计不保存原始参数值、用户正文、模型上下文或隐藏思维链。
- Phase 3 只有显式“保存草稿”动作可以把带确认凭据的提案写入 Store。
- 责任建议不会自动填写责任人；人工派工事件明确记录协调员、整改人和责任角色。
- 高风险关闭要求专业复查角色，且 actor ID 不能与原报告人相同。
- 旧 revision 请求冲突；取消记录终止后续动作；事件轨迹只追加、不由客户端回传覆盖。
- 资料不作为系统指令；检索不会调用第二个模型、执行资料中的命令或写入业务状态。
- 未确认地区、境外范围、到复核期限/撤回/损坏资料不返回引用；无依据明确提示人工核对。
- 图片内文字不作为系统指令，视觉Agent无工具或状态写入；高风险候选纠正后仍必须人工复核。
- 视觉结果、人工候选决定、照片关联独立保存；主状态仍只由原工作流推进，不把附图误作复查通过。
- 图片关联遵循“先工作流锁、后照片锁”的固定顺序，仅保证单进程一致性，不是跨主机事务。
- 聊天图片必须逐次外发授权，且只有已配置的视觉模型可达；图片及图内文字是未核实的用户资料，不是系统指令或工具权限。
- 含图片的工程分析强制人工复核，单张图片不构成安全、质量或责任认定；图片不改变工单状态。
