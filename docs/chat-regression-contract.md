# 统一聊天回退修复

目标：恢复逐轮对话，提供快速/深度思考选择，将供应商正文增量及时展示。
教程依据：Hello-Agents V1.0.3 第7章单Agent、第9章完整问答上下文、第12章回归和Extra09可观测性。
当前行为：auto入口漏掉助手历史，所有请求强制high；完整结果返回后才分段展示。
允许修改：文字适配、产品请求v4、NDJSON、会话组件及相关测试/文档。
禁止修改：冻结v1–v3契约、工单权限/状态机、图片/RAG、密钥、依赖或未经授权的真实调用。
测试命令：专项pytest、前端行为测试、scripts/verify.ps1、隔离浏览器桌面/移动检查。
人工确认点：工单仍只由完整校验结果触发申请，保存/派工需人确认；真实效果与延迟另行抽样。

## 验收条件

- R01：auto的“解释人工智能 → 你好 → 把上一段改短”保持user/assistant配对，末条仅当前输入。
  仅服务端成功答复进入历史；失败、重放不追加；最近12对/120000字裁剪包括助手回答。
- R02：新增thinking_mode=fast/deep，默认fast；fast显式disabled且不发reasoning_effort，
  deep显式enabled/high。保留32768输出预算和180秒上限，不硬编码问候答案，不以延时假装思考。
  旧chat/consult接口原行为兼容；新UI按每次发送快照显示选择，等待时不能切换。
- R03：auto流式端点向供应商发stream=true，只读delta.content；JSON以answer字符串开头，
  有界增量解码该字符串（包括跨块转义/Unicode），不把JSON、分析或隐藏reasoning当正文。
  若供应商不按answer优先顺序输出，安全回退为完整校验后的展示，不自动重试或再付费调用。
- R04：生成中正文是临时展示，不是已核验工程结论；完整JSON通过Pydantic与风险门禁后才提交
  会话/工单资格。失败/截断/断流清掉临时正文、恢复输入、不提交历史、不跳工单；已有高风险会话
  不提前展示可能被风险保留规则替换的正文。最终答案为唯一事实，不重复追加。
- R05：NDJSON有界队列、正文总长64000 Unicode字符、每段最多1000字符、事件最多64000段；
  无人为打字sleep；断开连接尽早停止消费并关闭流（不保证供应商立即停止计费）。
- R06：保留日期/型号系统事实、自然对话提示词、工单AI分类与人工确认；普通问题不要求填现场字段。
- R07：Fake SDK阻塞尾块，消费端在释放尾块前收到正文，以证明真流式；不以Fake耗时声称真实首字速度。

本契约替代统一聊天契约的“完整结果后分段展示”和“固定high”部分；旧契约保留历史记录。
供应商参数核对：[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、
[流式API](https://api-docs.deepseek.com/api/create-chat-completion/)。
