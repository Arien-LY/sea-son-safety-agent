交付边界（2026-09-13）：

- 单进程本机存储，最多200会话，不提供删除/归档或多进程共享；损坏文件不覆盖，聊天读写报错，工作台仍可启动。
- 180秒为应用预算，网络调用另有超时；停止浏览器等待不能保证远端停止计费。工具开启时最多3次模型请求，每次8192输出token，不自动重试。
- DeepSeek 深度工具轮次仅暂存和回传协议要求的 opaque reasoning_content，不展示、不记录、不落盘；普通无工具路径保持原隔离。
- C09 当前落实 DeepSeek 模型与 Tavily 搜索凭据隔离、未知供应商拒绝。腾讯分支没有合并，也没有宣称腾讯能力已实现。
- 来源按回答保存和展示；工具原始全文及工具调用协议不进入跨轮持久上下文。追问具体网页时可直接提供来源链接。
- 客户配置真实模型及独立搜索凭据后仍需真实服务验收。本次测试不代表模型工程判断质量或付费服务可用性。
- 仅本地增量功能与工单交接局部修复；没有重写框架、升级依赖或改变业务状态机。回滚使用基线单独检出，保留并备份新增数据库；不自动删除用户记录。

多模态附件增量（2026-09-18）：

- 目标：把聊天 composer 已接受的缩略图附件接到真实请求链，不改工单状态机、不改 `.env`、不新增上传接口。
- 契约：产品文字请求 v6 新增可选 `photo_id`（`^PHOTO-[A-F0-9]{24}$`）与 `allow_image_external`，
  响应新增 `photo_id`；v1–v5 快照不变。`intent=consult` 不接受图片；只发图片时服务端补默认描述。
- 链路：前端上传 → 原 `/api/photos`（真实格式检查、安全解码、清除元数据、标准化 JPEG）→ 同一文字请求
  → 聊天服务从 PhotoStore 读取并校验完整性 → 原单 Agent 与工具循环。
- 外发：仅 real 模式、本次 `allow_image_external=true` 且 `VISION_MODEL` 已配置时才外发；
  格式为 DeepSeek Chat Completions 最后一条 user 的 `text` + `image_url` 数据 URL（JPEG，`detail=original`），
  不传公网图片 URL，不保存 base64。Mock 不外发、不识图，界面也不声称使用视觉模型。
- 幂等与持久化：旧纯文字请求哈希排除新增默认字段，图片轮次哈希包含图片字段；会话只保存图片 ID。
- 人工边界：含图片的工程类分析强制 `requires_human_review=true` 且路由 `human_review`，仍由人工确认建单。
- 回滚：撤销本增量即回到“composer 本地预览”，不改存储格式、原图片证据链与工单流程。
