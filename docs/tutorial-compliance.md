# Hello-Agents V1.0.3 教程符合性

避免只在文档中声称“参考教程”。

## 可机械检查的规则

- Python 固定 3.12；依赖必须锁定或给出明确兼容范围。
- `hello-agents==0.2.9` 与本地 V1.0.3 教程示例兼容；升级必须单独 PR 验证 API 变化。
- Pydantic 模型默认 `extra="forbid"`，阻止模型偷偷扩展字段。
- 工具统一返回 `ToolResult`，错误包含稳定 `error_code`。
- Agent 最大步骤、超时和重试必须有上限。
- 测试默认 Fake/Mock；普通 `verify.ps1` 不访问外部模型。
- 每个阶段在 `TASKS.md` 具有固定输入、输出、验收和禁止范围。
- 新增 RAG、图片或多智能体前必须有前一阶段的验证记录。

## Phase 4 落地

Phase 4 落地：第 8 章采用小规模本地候选检索，不把向量数据库作为前置条件；第 9 章用最大3条
短释义和严格出处边界控制上下文，资料不进入系统指令、不额外触发模型循环。第 7 章继续提供原生
Function Calling Schema 和统一 ToolResult；Extra09 复用有容量上限的脱敏工具审计。
实现与验收见 `docs/phase4-knowledge-contract.md`，未进行真实模型工具选择或开放域检索效果评估。

## Phase 5 落地

Phase 5 延续单Agent和结构化输出原则：临时SimpleAgent只做一次视觉调用，不启用其自然语言工具
标记解析；适配层使用官方原生多模态content块。图片安全解码、确认、证据关联和主状态权限由代码
负责；Fake协议测试、合成图连通性和专业现场评估分开记录，不把图片模型升级当成自动判断权升级。

## Phase 6 评估落地

第12章与Extra09落地为严格的评估运行、单案例Trace和报告Schema：20条冻结案例逐项计算分类、字段、
高风险、路由和工具门禁；成功/失败事件只含案例摘要、枚举、计数和时间，不保存正文、Prompt、密钥或
隐藏思维链。合成协议、真实模型和人工裁决由`run_kind`分离；缺失usage、账单或闭环裁决时输出
`not_measured`。普通`verify.ps1`只运行合成回放，不实例化模型或访问网络。

## 产品补齐落地

产品补齐延续第7/9章：单轮SimpleAgent原生JSON响应，服务端提供最多6轮用户输入和上轮已校验追问，
不接受客户端系统历史。风险保留、费用同意、提案资格及正式状态仍由确定性代码负责；提案复用已知工具
的程序调用路径，不额外支付一次模型费用来选择唯一工具。浏览器/协议测试与真实模型效果验收分开记录。

会话工作台只重组前端信息架构，不扩大 Agent 权限：普通聊天不提供提案入口；专业咨询仅在服务端最新
分析具备资格后显示提案动作；直接提交仍经过预览、人工确认、HMAC 完整性和显式保存。历史侧栏只读取
正式 Store，不把浏览器会话建立为第二状态源。

日常聊天体验修订按第7/9章最小对话原则，将 `intent=chat` 从专业结构化分析中分离：复用模型适配层
执行一次有超时、输出长度和零重试限制的无工具调用，服务器日期及有限用户上下文随请求提供；
不使用本地关键词或日期硬编码替代模型回答。自由文本经过长度检查及 Pydantic `ChatReply` 校验，
风险字段由程序保守标为未分析，不能生成提案；`consult` 仍使用原 SimpleAgent 严格 JSON 路径。
第12章/Extra09验收增加真实 Vue 组件行为测试和隔离延迟 Fake 浏览器测试，不以 Fake 耗时声称真实模型性能。

普通聊天逐轮上下文修复落实第9章历史与当前任务分离：历史使用服务端成功响应配对user/assistant，
当前问题是独立末条user；不把咨询用的累计问题包当作普通聊天当前问题。第12章通过HTTP→实际适配器→
Fake SDK检查三轮角色顺序、失败重试及幂等，不以预设回答声称真实模型重复率已降低。

普通聊天容量升级继续落实第9章预算：开启供应商思考模式high，增加合理输出/时间/会话上限，不要求
模型填满预算。历史裁剪只移除完整旧问答并明确提示，安全规则仍常驻system与代码。
产品Schema新增v2，Phase1/3及v1冻结文件不改；咨询风险与工单权限不放宽。
不读取、保存、展示或回传隐藏reasoning_content；已开启思考的状态是配置事实，不是内部步骤窥视。

## 统一聊天回退修复

统一入口回退修复按第9章复用完整成功问答对，末条仅当前问题；日期与型号作为服务端事实提供。
按第7/12章增加快速/深度选择与真实供应商正文流式：临时正文无业务权限，完整Pydantic/JSON校验后
才提交会话和工单资格；既有高风险覆盖前不提前输出模型正文，失败清除临时展示。
不读取隐藏reasoning、不增加模型轮次；供应商阻塞尾块测试证明首段能在最终结果前到达，
并不把离线Fixture响应速度当作真实模型性能。契约见`docs/chat-regression-contract.md`。

## 教程源码

聊天正文失败隔离继续保留第7章Pydantic边界：auto先验证完整JSON和正文，再独立验证工单分析。
分析不可用仅影响工单权限，由程序生成未判断占位与独立响应状态；保留已验证正文进入完整问答历史。
旧consult严格路径与已有高风险保留不变；模型不能声明自己校验通过。第12章回归先复现10项失败，
验证正文保留、幂等、旧工单资格撤销及无额外付费调用；见chat-answer-isolation-contract。
